<section class="role">
    <div class="role-head"><span><strong>Machine Learning Engineer</strong> | <em>Orbio Earth (YC S23)</em></span><span class="role-date">June 2024 to June 2025</span></div>
    <p class="role-summary"><em>Methane detection in satellite imagery with computer vision.</em></p>

- The company built a model that finds methane plumes in satellite scenes.  I worked on the data path, the training stack and the release process.
- **Release process.** I set up a Model Release Process across ML, QA and engineering.  It covers versioning, documentation and sign-off.  It was the first formal path from an experiment to production at the company.  I mentored two engineers into it.
- **Data path.** Scenes were tiled into chips with rasterio.  The chips were stored as NumPy arrays in Parquet.  Methane plumes were simulated into chips at load time.  The chips moved from float32 to int16, which halved the storage and the I/O bandwidth.  The chip size moved from 128 px to 256 px, for more model context and better I/O efficiency.
- I tuned the Parquet layout for three competing needs: random sampling, correlation between rows in the same batch, and sequential I/O.  A row group size was chosen to balance them.  A row group index made sampling a targeted read.  I chose zstd at level 9 for the codec.  Decompression speed stays close to flat across levels, so a high level costs only write time.  The storage side is described in <a href="/posts/parquet_metadata/">Creating Memory Leaks with Parquet Metadata</a>.
- **Training.** I moved training from DataParallel to DistributedDataParallel.  I tuned the DataLoader for workers, pinned memory, prefetching and persistent workers.  I also right-sized the cluster.  GPU utilisation rose from 50 to 60 percent to about 90 percent.  Training time roughly halved.  The training changes came with a move from two GPUs to four larger GPUs, so the utilisation figure is the cleaner measure of the data path work.  The training loop is described in <a href="/posts/torch-distributed-explained/">Distributed Training with DistributedDataParallel</a>.
- I improved the model's recall by sourcing synthetic training data that was closer in distribution to real data.  I rewrote a cloud map-reduce job to run on a single machine.  The rewrite removed days of runtime and a four-figure compute bill for each run.
- When the company shut down, I open-sourced the methane pipeline as <a href="https://orbio-earth.github.io/Project-Eucalyptus/">Project Eucalyptus</a>.  It is a public guide to training data, tiling, validation and plume quantification.

</section>

<h2>Projects</h2>

<section class="project">
<h3>Database for multidimensional data (in progress)</h3>
    <p>This is an OLAP database for multidimensional data, written in Rust with SQL served through Apache DataFusion.  Each record is indexed on a Z-order key as it arrives.  The index keeps the same structure for any insertion order, and it is designed for skewed value distributions.  It targets spatial and spatiotemporal data, telemetry and log streams, and other records with several numeric attributes that are queried together.</p>

- Data is stored in column-contiguous segments on disk.
- SQL is parsed and planned by Apache DataFusion, with custom operators for spatial and multidimensional access.
- Supports concurrent workloads: multiple ingest threads write to the index at the same time, and queries run during ingest.
</section>

<section class="project">
<h3>Timelapse Tools</h3>
    <p>Timelapse Tools lets photographers edit and render timelapses from a sequence of camera RAW, HEIC or still images, as a native Apple app with a companion command-line tool.  Its built-in editor keyframes adjustments and removes flicker across the sequence, then exports to H.264, HEVC, ProRes or GIF.  Rendering stays on the GPU, and memory stays flat however many frames a timelapse has.</p>
</section>
